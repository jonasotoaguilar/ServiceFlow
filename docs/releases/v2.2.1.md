# v2.2.1 — Fix-forward publication with native builders

Patch release that publishes the unpublished `v2.2.0` application payload through the native-builders release pipeline already merged to `main`. Tag `v2.2.0` did not complete publication and remains immutable with no published artifacts; `v2.2.1` carries its full content plus the publication fix. No auth behavior, session, or `authRule` change beyond what `v2.2.0` described.

## What changed

### Unpublished `v2.2.0` payload, republished

Dedicated `/resend-verification` experience: login shows a "Reenviar verificación" link instead of an always-visible resend button. The resend form gates submission on a valid email, keeps the enumeration-neutral acknowledgement ("Si el correo está registrado y pendiente de verificación, te enviamos un enlace."), adds Spam/Junk guidance after submit, and the `/verify` result card links to `/resend-verification` ("Solicitar un nuevo enlace").

Spanish verification email template in `pocketbase/v1.collections.json` (subject "Verifica tu correo de {APP_NAME}", matching body, Spam guidance line). Tokens and callback are unchanged: `{APP_NAME}`, `{APP_URL}`, `{TOKEN}`, `{APP_URL}/verify?token={TOKEN}`.

ServiceFlow SVG favicon: binary `app/favicon.ico` replaced by vector `app/icon.svg` (bolt on brand `#2F5B8A`) via the Next.js icon convention.

### Native-builders publication fix

The `v2.2.0` publication run was cancelled by a QEMU ARM64 fault and produced no GitHub Release or GHCR artifacts. The pipeline now builds each architecture natively — `amd64` on `ubuntu-24.04`, `arm64` on `ubuntu-24.04-arm` — with no QEMU emulation, then assembles the multi-arch manifest with `docker buildx imagetools create` before `gh release create --verify-tag`. Per-arch jobs use a 30 minute limit with fail-fast `timeout(1)` guards (20 minute build, 10 minute manifest) inside the 45 minute publication limit. Least-privilege token handling is preserved: job-level blank `GITHUB_TOKEN` with step-scoped tokens only where required.

Release issue [#123](https://github.com/jonasotoaguilar/serviceflow/issues/123). Publication fix: [#122](https://github.com/jonasotoaguilar/serviceflow/pull/122). Unpublished payload: [#119](https://github.com/jonasotoaguilar/serviceflow/issues/119), [#118](https://github.com/jonasotoaguilar/serviceflow/pull/118).

## Install

```sh
docker pull ghcr.io/jonasotoaguilar/serviceflow:v2.2.1
docker run --rm -p 3000:3000 ghcr.io/jonasotoaguilar/serviceflow:v2.2.1
```

For local development:

```sh
pnpm install --frozen-lockfile
pnpm run build
pnpm start
```

Environment variables follow `.env.example` (`POCKETBASE_URL`, `APP_PORT`, `POCKETBASE_PORT`, `POCKETBASE_ADMIN_EMAIL`, `POCKETBASE_ADMIN_PASSWORD`, `PB_SMTP_PASSWORD`, `PB_META_APP_URL`); see `docs/RELEASING.md` for toolchain and release contract.

## Upgrade

Upgrade is in-place from `v2.1.0`. Pull the immutable `v2.2.1` image, then re-run `pocketbase-init` (or transcribe the equivalent collection import) so the updated Spanish verification email template reaches existing PocketBase instances — the template lives in the imported collections, not in the app image.

There is no data migration, no session invalidation, and no `users.authRule` change: sessions issued under `v2.1.0` keep working.

Record the current image digest before upgrading:

```sh
docker buildx imagetools inspect ghcr.io/jonasotoaguilar/serviceflow:latest --raw | sha256sum > /tmp/pre-v2.2.1-digest.txt
cat /tmp/pre-v2.2.1-digest.txt
```

Then pull and validate:

```sh
docker pull ghcr.io/jonasotoaguilar/serviceflow:v2.2.1
docker pull ghcr.io/jonasotoaguilar/serviceflow:2.2
docker pull ghcr.io/jonasotoaguilar/serviceflow:2
docker pull ghcr.io/jonasotoaguilar/serviceflow:latest
docker buildx imagetools inspect ghcr.io/jonasotoaguilar/serviceflow:v2.2.1 --raw | sha256sum
```

The composed app is at `http://127.0.0.1:${APP_PORT:-3000}` and PocketBase at `http://127.0.0.1:${POCKETBASE_PORT:-8090}`.

## Known issues

- Verification mail deliverability depends on sender reputation; if the message does not arrive within a few minutes, check Spam or Junk. This is operational guidance, not a defect.
- Operator staging mail sends stay outside the default test suite.

## Rollback

To revert a deployment upgraded to `v2.2.1` before the next patch:

```sh
PRE_DIGEST="$(cat /tmp/pre-v2.2.1-digest.txt)"
docker pull "ghcr.io/jonasotoaguilar/serviceflow@${PRE_DIGEST}"
docker tag "ghcr.io/jonasotoaguilar/serviceflow@${PRE_DIGEST}" ghcr.io/jonasotoaguilar/serviceflow:rollback-pre-v2.2.1
docker run --rm -p 3000:3000 "ghcr.io/jonasotoaguilar/serviceflow@${PRE_DIGEST}"
```

If no digest was recorded, redeploy `v2.1.0`. Do not move the `v2.2.1` or `v2.2.0` tags or delete published GitHub Releases or GHCR images; failures are fixed forward with the next patch.
