# v2.2.0 — Dedicated verification resend and Spanish verification mail

Minor release that moves verification resend out of the login form into a dedicated `/resend-verification` experience, translates the PocketBase verification email template to Spanish, and replaces the binary favicon with a ServiceFlow SVG icon. No auth behavior, session, or `authRule` change.

## What changed

### Dedicated `/resend-verification` experience

The always-visible resend button is gone from the login form; login now shows a "Reenviar verificación" link to the dedicated `/resend-verification` page instead. The new resend form gates submission on a valid email (submit stays disabled until the address parses), keeps the enumeration-neutral acknowledgement ("Si el correo está registrado y pendiente de verificación, te enviamos un enlace."), and adds Spam/Junk guidance after submit. The `/verify` result card now links to `/resend-verification` ("Solicitar un nuevo enlace") alongside the login link.

### Spanish verification email template

`pocketbase/v1.collections.json` carries the verification template in Spanish (subject "Verifica tu correo de {APP_NAME}", matching body) and adds a "revisa Spam o Correo no deseado" line. Safe tokens and callback are unchanged: `{APP_NAME}`, `{APP_URL}`, `{TOKEN}`, and the `{APP_URL}/verify?token={TOKEN}` link.

### ServiceFlow SVG favicon

The binary `app/favicon.ico` is replaced by a vector `app/icon.svg` (ServiceFlow bolt on brand `#2F5B8A`), served through the Next.js icon convention.

Release issue [#119](https://github.com/jonasotoaguilar/serviceflow/issues/119). Feature: [#118](https://github.com/jonasotoaguilar/serviceflow/pull/118).

## Install

```sh
docker pull ghcr.io/jonasotoaguilar/serviceflow:v2.2.0
docker run --rm -p 3000:3000 ghcr.io/jonasotoaguilar/serviceflow:v2.2.0
```

For local development:

```sh
pnpm install --frozen-lockfile
pnpm run build
pnpm start
```

Environment variables follow `.env.example` (`POCKETBASE_URL`, `APP_PORT`, `POCKETBASE_PORT`, `POCKETBASE_ADMIN_EMAIL`, `POCKETBASE_ADMIN_PASSWORD`, `PB_SMTP_PASSWORD`, `PB_META_APP_URL`); see `docs/RELEASING.md` for toolchain and release contract.

## Upgrade

Upgrade is in-place from `v2.1.0`. Pull the immutable `v2.2.0` image, then re-run `pocketbase-init` (or transcribe the equivalent collection import) so the updated Spanish verification email template reaches existing PocketBase instances — the template lives in the imported collections, not in the app image.

There is no data migration, no session invalidation, and no `users.authRule` change: sessions issued under `v2.1.0` keep working.

Record the current image digest before upgrading:

```sh
docker buildx imagetools inspect ghcr.io/jonasotoaguilar/serviceflow:latest --raw | sha256sum > /tmp/pre-v2.2.0-digest.txt
cat /tmp/pre-v2.2.0-digest.txt
```

Then pull and validate:

```sh
docker pull ghcr.io/jonasotoaguilar/serviceflow:v2.2.0
docker pull ghcr.io/jonasotoaguilar/serviceflow:2.2
docker pull ghcr.io/jonasotoaguilar/serviceflow:2
docker pull ghcr.io/jonasotoaguilar/serviceflow:latest
docker buildx imagetools inspect ghcr.io/jonasotoaguilar/serviceflow:v2.2.0 --raw | sha256sum
```

The composed app is at `http://127.0.0.1:${APP_PORT:-3000}` and PocketBase at `http://127.0.0.1:${POCKETBASE_PORT:-8090}`.

## Known issues

- Verification mail deliverability depends on sender reputation; if the message does not arrive within a few minutes, check Spam or Junk. This is operational guidance, not a defect.
- Operator staging mail sends stay outside the default test suite.

## Rollback

To revert a deployment upgraded to `v2.2.0` before the next patch:

```sh
PRE_DIGEST="$(cat /tmp/pre-v2.2.0-digest.txt)"
docker pull "ghcr.io/jonasotoaguilar/serviceflow@${PRE_DIGEST}"
docker tag "ghcr.io/jonasotoaguilar/serviceflow@${PRE_DIGEST}" ghcr.io/jonasotoaguilar/serviceflow:rollback-pre-v2.2.0
docker run --rm -p 3000:3000 "ghcr.io/jonasotoaguilar/serviceflow@${PRE_DIGEST}"
```

If no digest was recorded, redeploy `v2.1.0`. Do not move the `v2.2.0` or `v2.1.0` tags or delete published GitHub Releases or GHCR images; failures are fixed forward with the next patch.
